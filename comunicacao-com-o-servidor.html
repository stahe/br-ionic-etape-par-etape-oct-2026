    9. Comunicação com o servidor

    O servidor JSON do [RdvMedecins] deve agora ser iniciado (porta 8080), como explicado no capítulo anterior, de preferência no modo de teste do CAPTCHA ([CAPTCHA_TEST=test]), que permite responder “test” a qualquer imagem.

    Os exemplos 22 a 25 compartilham alguns arquivos, localizados na pasta [src/app/common/] do projeto: o endereço do servidor ([config.ts]), os tipos de resposta ([types.ts]), as classes de erro ([api-error.ts]), o serviço de requisições ([api.ts]) e uma barra de login ([login-bar.ts]). Eles são apresentados ao longo dos exemplos, à medida que se tornam relevantes.

    9.1.1. Onde está o servidor?

Uma aplicação instalada em um celular não tem uma origem utilizável: sua página é servida pelo próprio [Capacitor] , a partir de https://localhost.     // =========================================================================
// src/app/common/config.ts - ONDE está o servidor JSON?
// -------------------------------------------------------------------------
// A pergunta não se coloca para uma aplicação web servida pelo
// próprio servidor: as requisições vão para a MESMA origem da página
// (um endereço relativo, /api/...). Mas uma aplicação MOBILE não tem origem
// utilizável (no Android, a página é servida pelo Capacitor
// a partir de https://localhost): é preciso informar-lhe o endereço completo do servidor.
//   - no desenvolvimento web (ng serve), o servidor de desenvolvimento
//     do Angular encaminha as requisições /api ao servidor JSON (arquivo
//     proxy.conf.json): um endereço relativo basta;
//   - o emulador Android enxerga o computador que o executa
//     no endereço 10.0.2.2 (localhost, para ele, é o próprio emulador);
//   - um celular real, conectado à mesma rede Wi-Fi do computador, deve
//     usar o endereço do computador nessa rede (192.168.1.20...):
//     ele é informado ao compilar a aplicação:
//         ng build --define "SERVER='http://192.168.1.20:8080'"
//     ou então alteramos a constante androidServer abaixo.
// =========================================================================

import { Capacitor } from '@capacitor/core';

// o endereço do servidor para a aplicação Android, quando nada mais é
// imposto: o do computador, visto do emulador
const androidServer = 'http://10.0.2.2:8080';

// o valor dado por --define "SERVER='...'" na compilação
// (ng build, ng serve). A opção substitui, no código compilado, a palavra
// SERVER pelo valor informado. Sem ela, SERVER não existe: typeof
// nos permite verificá-lo sem causar um erro
declare const SERVER: string | undefined;
const forcedServer = typeof SERVER === 'string' ? SERVER : '';

export const config = {
  // Capacitor.isNativePlatform(): true na aplicação Android (ou iOS),
  // false em um navegador; Capacitor.getPlatform(): 'android', 'ios' ou 'web'
  serverUrl:
    forcedServer !== ''
      ? forcedServer
      : !Capacitor.isNativePlatform()
        ? '' // a web: mesma origem, endereços relativos
        : Capacitor.getPlatform() === 'android'
          ? androidServer
          : 'http://localhost:8080',
};
    • linha 21: [Capacitor], o objeto de [@capacitor/core] que fornece informações sobre a plataforma em que a aplicação está sendo executada. Ele pode ser usado em qualquer lugar, inclusive em um navegador;
    • linha 25: o endereço padrão é o do [Android]. O emulador é uma máquina independente com sua própria rede: para o emulador, [localhost] refere-se ao próprio emulador. O endereço especial [10.0.2.2] refere-se ao computador que o executa;
    • linhas 31–32: um endereço imposto durante o build da aplicação pela opção [--define] do [Angular]: [ng build --define "SERVER='http://192.168.1.20:8080'"]. A compilação substitui o identificador [SERVER] no código pelo valor informado (uma string, daí os apóstrofos). Sem essa opção, [SERVER] não existe: [declare const] informa ao compilador [TypeScript] que [SERVER] é um identificador que ele não vê declarado, e [typeof SERVER] permite testar sua existência sem causar um erro. Este é o equivalente exato de [--dart-define] e de [String.fromEnvironment] no [Flutter];
    • linhas 34–45: caso contrário, um endereço específico da plataforma. [Capacitor.isNativePlatform()] é verdadeiro na aplicação [Android] (ou [iOS]), mas falso em um navegador; [Capacitor.getPlatform()] retorna 'android', 'ios' ou 'web':
    • no navegador (linha 41): uma URL relativa (''), portanto a mesma origem da aplicação;
    • no [Android] (linha 43): o endereço da linha 25;
    • em outros casos (linha 44, [iOS], que este curso não aborda): [localhost].

    Um celular real, conectado à mesma rede Wi-Fi do computador servidor, deve usar o endereço do computador nessa rede (o comando [ipconfig] do [Windows] o fornece): você pode passá-lo por meio de [--define] durante a compilação ou modificar a constante da linha 25. O firewall do computador também deve permitir conexões de entrada na porta 8080.

// capacitor.config.ts - a configuração do Capacitor
// -------------------------------------------------------------------------
// O Capacitor transforma a aplicação web (a pasta produzida por ng build)
// em uma aplicação Android: ele a encapsula em um projeto do Android Studio
// (pasta android/), onde é exibida por uma "WebView", o motor do
// navegador Chrome do celular. Comandos (veja o exemplo 01, "Execução"):
//     npx cap add android       (uma única vez: cria a pasta android/)
//     ng build                  (compila a aplicação web)
//     npx cap sync android      (copia-a para o projeto Android)
//     npx cap run android       (executa em um emulador ou em um celular)
// =========================================================================

import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  // o identificador único da aplicação no celular (e na Play Store)
  appId: 'fr.stahe.examples',
  // o nome exibido sob o ícone
  appName: 'Ionic Examples',
  // a pasta da aplicação web compilada (ng build)
  webDir: 'dist/examples_ionic/browser',
  server: {
    // permite requisições HTTP não criptografadas (http://10.0.2.2:8080) para
    // o servidor JSON de desenvolvimento (exemplos 22 a 25)
    cleartext: true,
  },
  plugins: {
    // CapacitorHttp: as requisições HTTP da aplicação deixam de ser feitas
    // pela WebView e passam a ser feitas pelo código nativo do Android. Consequências (veja
    // os exemplos 22 e 23): sem verificação de CORS (o servidor JSON não precisa
    // liberar nada), e os cookies (o do token de autenticação) são
    // armazenados pelo Android e reenviados automaticamente
    CapacitorHttp: {
      enabled: true,
    },
  },
};

export default config;
    • Linhas 23–27: [server.cleartext: true]. A partir da versão 9 do [Android], uma aplicação só tem permissão para se comunicar usando HTTPS. Nosso servidor de desenvolvimento usa HTTP: nós o permitimos. O comando [npx cap sync android] transfere essa configuração para o projeto [Android] (o atributo [android:usesCleartextTraffic="true"], adicionado ao manifesto que o [Capacitor] mescla com o manifesto da aplicação). Em produção, o servidor estaria em HTTPS, e essa configuração desapareceria;
    • linhas 28–37: o plugin [CapacitorHttp]. As requisições HTTP da aplicação (as do cliente HTTP do [Angular], assim como as do [fetch]) deixam de ser enviadas pela WebView e passam a ser enviadas pelo código nativo do [Android]. Para um navegador, a aplicação (https://localhost) e o servidor (http://10.0.2.2:8080) pareceriam ter duas origens diferentes: o navegador exigiria que o servidor fornecesse uma autorização CORS, que o servidor não concede, e se recusaria a incluir o cookie do token. O código nativo não tem essas regras. O código [TypeScript] da aplicação, porém, não muda: é o [Capacitor] que redireciona as requisições.

    // =========================================================================
// src/app/ex22-http/ex22.page.ts - uma primeira requisição HTTP ao servidor
// -------------------------------------------------------------------------
// O servidor JSON do RdvMedecins deve estar em execução (porta 8080). Pedimos-lhe
// um captcha: GET /api/captcha -> { "id": "...", "svg": "<svg ...>" }.
//
//   - HttpClient: o cliente HTTP do Angular (fornecido a toda a aplicação
//     por provideHttpClient(), em main.ts). http.get<T>(address) retorna
//     um Observable: a requisição é enviada quando nos INSCREVEMOS nele (subscribe), e
//     a resposta chega depois, com seu corpo JSON já decodificado;
//   - uma resposta de erro (4xx, 5xx) ou a ausência de resposta chegam
//     na função error da inscrição;
//   - o endereço do servidor depende de onde a aplicação executa
//     (navegador, emulador Android, celular): veja common/config.ts;
//   - três estados a exibir: carregando, com sucesso, com erro;
//   - a imagem do captcha é SVG: uma tag <img> pode exibi-la.
// =========================================================================

import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { Component, DestroyRef, inject, signal } from '@angular/core';
import {
  IonBackButton, IonButton, IonButtons, IonCard, IonCardContent, IonContent, IonHeader, IonNote, IonProgressBar,
  IonTitle, IonToolbar,
} from '@ionic/angular';
import { Subscription } from 'rxjs';
import { config } from '../common/config';
import { Captcha, captchaImage } from '../common/types';

@Component({
  selector: 'app-ex22',
  imports: [
    IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle, IonContent, IonProgressBar, IonCard, IonCardContent,
    IonButton, IonNote,
  ],
  templateUrl: './ex22.page.html',
  styles: `
    .error { --background: #ffebee; --color: #333; margin: 12px 0; }
    .image { border: 1px solid #ddd; border-radius: 6px; padding: 4px; text-align: center; }
    .image img { height: 60px; }
    .id { font-family: monospace; font-size: 11px; margin: 8px 0; }
  `,
})
export class Ex22Page {
  private readonly http = inject(HttpClient);
  readonly server = config.serverUrl || '(same origin: /api, ng serve proxy)';
  readonly captchaImage = captchaImage;

  // o estado da tela: signals
  readonly captcha = signal<Captcha | null>(null);
  readonly loading = signal(true);
  readonly error = signal<string | null>(null);
  readonly requestCount = signal(0);

  // a inscrição na requisição em andamento (se houver)
  private request?: Subscription;

  constructor() {
    this.load(); // a primeira requisição, assim que a página é criada
    // a página destruída (botão Voltar): a requisição em andamento é abandonada
    inject(DestroyRef).onDestroy(() => this.request?.unsubscribe());
  }

  load(): void {
    // cancelar a inscrição em uma requisição ainda em andamento a CANCELA: sua resposta,
    // agora inútil, nunca será processada (nenhuma resposta "obsoleta")
    this.request?.unsubscribe();
    this.loading.set(true);
    this.error.set(null);
    // <Captcha>: o tipo do corpo JSON esperado (uma promessa feita ao
    // compilador: nada é verificado em tempo de execução)
    this.request = this.http.get<Captcha>(`${config.serverUrl}/api/captcha`).subscribe({
      // next: a resposta chegou (código 2xx), seu corpo JSON é decodificado
      next: (captcha) => {
        this.captcha.set(captcha);
        this.requestCount.update((n) => n + 1);
        this.loading.set(false);
      },
      // error: uma resposta de erro (4xx, 5xx), ou nenhuma resposta
      // (servidor parado, endereço errado: status é então 0)
      error: (e: HttpErrorResponse) => {
        this.error.set(e.status === 0 ? 'no response (status 0)' : `the server responded ${e.status}`);
        this.captcha.set(null);
        this.loading.set(false);
      },
    });
  }
}

    9.2. Exemplo 23: Login, cookie e sessão

    9.2.1. E o cookie?

    O servidor armazena o token JWT em um cookie. O cliente [Flutter] precisou, nesse ponto, substituir seu cliente HTTP por um que lê o cabeçalho [Set-Cookie] de cada resposta, organiza os cookies (e os armazena em o dispositivo) e os devolve no cabeçalho [Cookie] de cada requisição: uma aplicação [Flutter] não tem um navegador que faça isso por ela.

    Uma aplicação [Ionic], por outro lado, não tem nada a escrever:

    • no navegador do computador, é o navegador que armazena o cookie e o devolve, como faz com qualquer outro site. O proxy de [ng serve] atribui a mesma origem à aplicação e à API: o cookie [SameSite=Strict] é aceito e devolvido. O código da aplicação não pode ler nem escrever esse cookie ([HttpOnly]);
    • no [Android], o plugin [CapacitorHttp] (exemplo 22) encaminha as requisições pelo código nativo. O [Capacitor] configura, na inicialização da aplicação, o gerenciador de cookies do [Android] (o do WebView) como gerenciador das requisições nativas: os cookies recebidos são armazenados ali e devolvidos nas requisições seguintes ao mesmo servidor. Eles são mantidos no dispositivo (o nosso tem uma duração definida por [Max-Age=7200]; apenas os cookies “de sessão”, que não têm data de expiração, são apagados quando o aplicativo inicia): você continua conectado ao fechar e reabrir o aplicativo.

    O token, portanto, nunca é manipulado pelo código do aplicativo, nem armazenado em texto simples no dispositivo (o cliente [Flutter] o armazenava em [shared_preferences]).

// src/app/ex23-login/command.ts - uma AÇÃO, seu estado, seu resultado
// -------------------------------------------------------------------------
// Uma ação assíncrona (fazer login, salvar...) tem um estado que
// a tela deve mostrar: ela está EM EXECUÇÃO (botão desabilitado)? terminou
// com um ERRO (mensagem)? É o padrão "Command" dos
// guias de arquitetura (o do Flutter, por exemplo), reduzido ao essencial:
//
//     readonly loginCommand = new Command();
//     this.loginCommand.execute(() => this.logIn());   // starts the action
//     loginCommand.running(), loginCommand.error()      // its state
//
// Seu estado é feito de SIGNALS: o template que os lê é atualizado
// quando o command inicia e quando termina.
// =========================================================================

import { signal } from '@angular/core';

export class Command {
  private readonly _running = signal(false);
  private readonly _error = signal<unknown>(null);
  readonly running = this._running.asReadonly();
  readonly error = this._error.asReadonly();

  // executa a ação, se outra ainda não estiver em execução
  async execute(action: () => Promise<void>): Promise<void> {
    if (this._running()) return; // sem envio duplo (toque duplo no botão)
    this._running.set(true);
    this._error.set(null);
    try {
      await action();
    } catch (e) {
      this._error.set(e); // o erro é MANTIDO, para ser exibido
    } finally {
      // finally: executado em TODOS os casos, sucesso ou erro
      this._running.set(false);
    }
  }

  clearError(): void {
    this._error.set(null);
  }
}

    Uma ação assíncrona (fazer login, salvar etc.) tem um estado que a tela deve exibir: está em andamento (botão desabilitado)? Terminou com um erro (mensagem)? É o modelo “Command” dos guias de arquitetura (o do [Flutter] o chama assim), reduzido ao essencial. O curso de [React] usava, para isso, as “actions” do [React] 19 ([useActionState]).

    • Linhas 19–23: uma classe simples (cada tela cria a sua com [new]), cujo estado é formado por dois signals privados, expostos como somente leitura. O template que lê [running()] ou [error()] é atualizado quando o comando começa e quando termina: é o papel que [ChangeNotifier] e [ListenableBuilder] desempenhavam no [Flutter];
    • linhas 26–38: executar uma ação: se outra ação estiver em andamento, não faz nada (linha 27: evita o envio duplo se o botão for pressionado duas vezes); caso contrário, o comando passa a “em andamento”; em caso de exceção, o erro é registrado para ser exibido (linha 33); em todos os casos ([finally], linhas 34–37), o comando deixa de estar em andamento. O erro é do tipo [unknown]: em [JavaScript], qualquer valor pode ser lançado, e o [TypeScript] não sabe, portanto, o que o [catch] captura.

  login: string;
  name: string;
  role: string;

export class Ex23Page {
  private readonly http = inject(HttpClient);
  readonly captchaImage = captchaImage;

  readonly user = signal<User | null>(null); // null: ninguém está logado
  readonly doctors = signal<Doctor[]>([]);
  readonly captcha = signal<Captcha | null>(null);
  readonly ready = signal(false); // a verificação inicial terminou?
  readonly serverError = signal<string | null>(null);
  readonly loginCommand = new Command();
  // os campos do formulário, vinculados por [(ngModel)]
  readonly login = signal('admin');
  readonly password = signal('');
  readonly captchaAnswer = signal('');

  constructor() {
    this.checkSession();
  }

  private url(path: string): string {
    return `${config.serverUrl}/api${path}`;
  }

  // uma requisição GET cujo corpo JSON queremos. Uma resposta que não seja
  // 2xx (ou a ausência de resposta) rejeita a Promise com um HttpErrorResponse
  private read<T>(path: string): Promise<T> {
    return firstValueFrom(this.http.get<T>(this.url(path)));
  }

  // um POST: o objeto do corpo é enviado como JSON (cabeçalho content-type: application/json)
  private post<T>(path: string, body: object): Promise<T> {
    return firstValueFrom(this.http.post<T>(this.url(path), body));
  }

  async loadCaptcha(): Promise<void> {
    this.captcha.set(await this.read<Captcha>('/captcha'));
    this.captchaAnswer.set('');
  }

  private async loadDoctors(): Promise<void> {
    this.doctors.set(await this.read<Doctor[]>('/doctors'));
  }

  // 1. quem está logado? 200 -> o usuário; 401 -> ninguém
  private async checkSession(): Promise<void> {
    try {
      this.user.set(await this.read<User>('/auth/me'));
      await this.loadDoctors();
    } catch (e) {
      // instanceof: um teste de TIPO; e.status: o código de status (0: sem resposta)
      if (e instanceof HttpErrorResponse && e.status === 401) {
        await this.loadCaptcha();
      } else if (e instanceof HttpErrorResponse && e.status !== 0) {
        this.serverError.set(`The server responded ${e.status}.`);
      } else {
        this.serverError.set(`Is the RdvMedecins JSON server running (${config.serverUrl || 'port 8080'})?`);
      }
    }
    this.ready.set(true);
  }

  // o botão "Entrar": o Command executa a ação e guarda seu erro
  submit(): void {
    this.loginCommand.execute(() => this.logIn());
  }

  // 2. o login
  private async logIn(): Promise<void> {
    try {
      const user = await this.post<User>('/auth/login', {
        login: this.login().trim(),
        password: this.password(),
        captchaId: this.captcha()?.id,
        captcha: this.captchaAnswer(),
      });
      this.password.set('');
      this.user.set(user);
      await this.loadDoctors();
    } catch (e) {
      if (!(e instanceof HttpErrorResponse)) throw e;
      // e.error: o corpo JSON da resposta de erro, { statusCode, key, ... }
      const key: string = e.error?.key ?? 'ERRORS.SERVER_UNREACHABLE';
      await this.loadCaptcha(); // cada imagem só é usada uma vez
      // o erro que o Command vai guardar
      throw new Error(`${e.status} - ${messages[key] ?? key}`);
    }
  }

  // a mensagem do erro guardado pelo command
  errorMessage(): string {
    const error = this.loginCommand.error();
    return error instanceof Error ? error.message : String(error);
  }

  // 4. o logout
  async logOut(): Promise<void> {
    await this.post('/auth/logout', {});
    this.user.set(null);
    this.doctors.set([]);
    await this.loadCaptcha();
  }
}

// está NO endereço. Uma imagem SVG exibida por <img> não pode executar

export function captchaImage(c: Captcha): string {
  return `data:image/svg+xml;charset=utf-8,${encodeURIComponent(c.svg)}`;
}

  title: string;
  firstName: string;
  lastName: string;
}

  version: number; // bloqueio otimista: a ser reenviado com uma atualização
  login?: string; // opcional (?): apenas para o ADMIN

  endMinute: number;

  bookable: boolean;

// src/app/common/api-error.ts - UMA classe para todos os erros da API
// -------------------------------------------------------------------------
// Todas as respostas de erro do servidor RdvMedecins têm a mesma forma:
//   { "statusCode": 409, "key": "ERRORS.LOGIN_TAKEN", "params": {...}, "fields": {...} }
// Mas uma requisição também pode falhar de OUTRA FORMA: nenhuma resposta
// (rede fora do ar, servidor parado, endereço errado), ou uma resposta que não
// vem do nosso servidor (uma página de erro de um proxy). O cliente
// HTTP do Angular relata todas essas falhas com um HttpErrorResponse; nós
// o convertemos em UMA classe, ApiError, que carrega a chave de tradução
// enviada pelo servidor (e, se houver, seus parâmetros e o erro de
// cada campo).
// =========================================================================

import { HttpErrorResponse } from '@angular/common/http';

// um objeto { name: texto }
export type Texts = Record<string, string>;

// "extends Error": um erro JavaScript completo, que lançamos
// (throw) e capturamos (catch); message é "409 ERRORS.LOGIN_TAKEN"
export class ApiError extends Error {
  constructor(
    readonly statusCode: number, // 0: o servidor não respondeu
    readonly key: string, // p. ex.: 'ERRORS.LOGIN_TAKEN'
    readonly params: Texts = {},
    readonly fields: Texts = {},
  ) {
    super(`${statusCode} ${key}`);
    this.name = 'ApiError';
  }

  // uma resposta de erro do cliente HTTP do Angular -> um ApiError
  static fromResponse(response: HttpErrorResponse): ApiError {
    // status 0: nenhuma resposta (rede fora do ar, servidor parado, endereço errado)
    if (response.status === 0) {
      return new ApiError(0, 'ERRORS.SERVER_UNREACHABLE');
    }
    // error: o corpo da resposta, já decodificado se for JSON
    const body: unknown = response.error;
    if (isObject(body) && typeof body['key'] === 'string') {
      return new ApiError(response.status, body['key'], texts(body['params']), texts(body['fields']));
    }
    // sem key: o proxy ou a rede respondeu no lugar do servidor
    return new ApiError(
      response.status,
      response.status >= 500 ? 'ERRORS.SERVER_UNREACHABLE' : 'ERRORS.SERVER_ERROR',
    );
  }
}

// um "type guard": se a função retornar true, o TypeScript sabe que
// value é um objeto cujas propriedades podem ser lidas
function isObject(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

// um objeto JSON { "name": "ERRORS..." } -> Texts (vazio caso contrário)
function texts(json: unknown): Texts {
  if (!isObject(json)) return {};
  return Object.fromEntries(Object.entries(json).map(([key, value]) => [key, String(value)]));
}

import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { inject, Injectable } from '@angular/core';
import { firstValueFrom } from 'rxjs';
import { config } from './config';
import { ApiError } from './api-error';

export type Method = 'GET' | 'POST' | 'PUT' | 'DELETE';

// providedIn: 'root': uma única instância, para toda a aplicação
@Injectable({ providedIn: 'root' })
export class Api {
  private readonly http = inject(HttpClient);

  // <T>: o tipo da resposta esperada, escolhido pelo chamador
  async request<T>(method: Method, url: string, body?: unknown): Promise<T> {
    try {
      // http.request retorna um Observable; firstValueFrom o transforma em
      // Promise (a requisição é enviada nesse momento). Um objeto de corpo é enviado
      // como JSON (cabeçalho content-type: application/json, que o servidor exige
      // para um POST); a resposta JSON é decodificada (null se seu corpo estiver vazio)
      return await firstValueFrom(this.http.request<T>(method, `${config.serverUrl}/api${url}`, { body }));
    } catch (e) {
      // o cliente HTTP relata QUALQUER falha (4xx, 5xx, sem resposta) com um
      // HttpErrorResponse: nós o convertemos. O resto (uma anomalia) passa como está
      throw e instanceof HttpErrorResponse ? ApiError.fromResponse(e) : e;
    }
  }

  get<T>(url: string): Promise<T> {
    return this.request<T>('GET', url);
  }

  // um POST sempre tem um corpo JSON: {} por padrão
  post<T>(url: string, body: unknown = {}): Promise<T> {
    return this.request<T>('POST', url, body);
  }

  put<T>(url: string, body: unknown): Promise<T> {
    return this.request<T>('PUT', url, body);
  }

  delete<T>(url: string, body?: unknown): Promise<T> {
    return this.request<T>('DELETE', url, body);
  }
}

  success: boolean;
  text: string;
}

@Injectable()
export class ScheduleModel {
  private readonly rdvmedecins = inject(RdvMedecins);

  // ---- o estado ----
  readonly user = signal<User | null>(null);
  readonly doctors = signal<Person[]>([]);
  readonly clients = signal<Person[]>([]);
  readonly doctorId = signal<number | null>(null);
  readonly day = signal(formatDay(tomorrow()));
  readonly clientId = signal<number | null>(null);
  readonly schedule = signal<Schedule | null>(null);
  readonly loading = signal(false);
  readonly message = signal<Message | null>(null);

  private readonly cache = new Map<string, Schedule>();
  private readNumber = 0;

  // ---- valores calculados ----
  readonly loggedIn = computed(() => this.user() !== null);
  readonly isManager = computed(() => this.loggedIn() && this.user()?.role !== 'USER');

  // ---- as ações ----
  async changeUser(u: User | null): Promise<void> {
    this.user.set(u);
    this.doctors.set([]);
    this.clients.set([]);
    this.schedule.set(null);
    this.doctorId.set(null);
    this.message.set(null);
    this.cache.clear(); // os direitos mudaram: esquecemos tudo
    if (u === null) return;
    this.doctors.set(await this.rdvmedecins.getDoctors());
    // um USER receberia 403
    if (this.isManager()) this.clients.set(await this.rdvmedecins.getClients());
  }

  chooseDoctor(id: number): void {
    this.doctorId.set(id);
    this.message.set(null);
    this.readSchedule();
  }

  chooseDay(day: string): void {
    this.day.set(day);
    this.message.set(null);
    this.readSchedule();
  }

  chooseClient(id: number | null): void {
    this.clientId.set(id);
  }

  book(c: ScheduleSlot): Promise<void> {
    return this.act(
      () => this.rdvmedecins.book(this.day(), c.id, this.isManager() ? this.clientId() : null),
      `Slot ${timeRange(c)} booked.`,
    );
  }

  cancel(c: ScheduleSlot): Promise<void> {
    return this.act(() => this.rdvmedecins.cancelAppointment(c.appointmentId!), `Appointment of ${timeRange(c)} cancelled.`);
  }

  // uma ação, depois SEMPRE uma nova leitura da agenda: o SERVIDOR é a referência
  private async act(action: () => Promise<void>, success: string): Promise<void> {
    try {
      await action();
      this.message.set({ success: true, text: success });
    } catch (e) {
      this.message.set({ success: false, text: e instanceof ApiError ? e.message : String(e) });
    }
    await this.readSchedule();
  }

  private async readSchedule(): Promise<void> {
    const id = this.doctorId();
    if (id === null) return;
    const key = `${id}/${this.day()}`;
    const number = ++this.readNumber;
    // primeiro o cache (ou nada), depois a leitura
    this.schedule.set(this.cache.get(key) ?? null);
    this.loading.set(true);
    try {
      const read = await this.rdvmedecins.getSchedule(id, this.day());
      if (number !== this.readNumber) return; // uma leitura mais recente foi iniciada
      this.cache.set(key, read);
      this.schedule.set(read);
    } catch (e) {
      if (number !== this.readNumber) return;
      this.schedule.set(null);
      this.message.set({ success: false, text: e instanceof ApiError ? e.message : String(e) });
    }
    this.loading.set(false);
  }
}

  readonly titles = ['Mr', 'Mme', 'Melle', 'Dr']; // "Dr": o servidor vai recusá-lo
  readonly fullName = fullName;

  readonly user = signal<User | null>(null);
  readonly clients = signal<Person[]>([]);

  // o formulário: NENHUMA regra de validação, tudo é verificado pelo servidor
  readonly form = inject(NonNullableFormBuilder).group({
    title: ['Mr'],
    firstName: [''],
    lastName: [''],
    login: [''],
    password: [''],
  });
  // null: criação; caso contrário, o id do cliente modificado e a versão lida com seu registro
  readonly editedId = signal<number | null>(null);
  private version = 0;

  // a mensagem geral do último erro, e a de um sucesso
  readonly pageError = signal<ApiError | null>(null);
  readonly success = signal<Success | null>(null);
  // o envio ao servidor: um Command (exemplo 23), que diz se está em execução
  readonly sending = new Command();

  constructor() {
    addIcons({ languageOutline, createOutline, trashOutline });
    this.tr.start();
  }

  isAdmin(): boolean {
    return this.user()?.role === 'ADMIN';
  }

  private async reload(): Promise<void> {
    this.clients.set(await this.api.get<Person[]>('/clients'));
  }

  async onUserChange(u: User | null): Promise<void> {
    this.user.set(u);
    this.clients.set([]);
    if (u?.role === 'ADMIN') await this.reload();
  }

  // o erro de um campo, retornado pelo servidor, traduzido ('': sem erro)
  fieldError(field: Field): string {
    const key = this.form.controls[field].errors?.['server'];
    return typeof key === 'string' ? this.tr.t(key) : '';
  }

  private clearMessages(): void {
    this.pageError.set(null);
    this.success.set(null);
  }

  newForm(): void {
    this.editedId.set(null);
    this.version = 0;
    // reset: os valores iniciais, e nenhum erro mais
    this.form.reset();
    this.clearMessages();
  }

  edit(c: Person): void {
    this.editedId.set(c.id);
    // a VERSÃO lida com o registro volta com a modificação: se alguém
    // modificou o registro nesse meio-tempo, o servidor responderá 409 CONCURRENT_UPDATE
    this.version = c.version;
    this.form.reset({ title: c.title, firstName: c.firstName, lastName: c.lastName, login: c.login ?? '', password: '' });
    this.clearMessages();
  }

  // o botão "Salvar"
  submit(): void {
    this.sending.execute(() => this.save());
  }

  private async save(): Promise<void> {
    this.clearMessages();
    const input = { ...this.form.getRawValue(), version: this.version };
    const id = this.editedId();
    try {
      const client =
        id === null
          ? await this.api.post<Person>('/clients', input)
          : await this.api.put<Person>(`/clients/${id}`, input);
      this.newForm(); // formulário esvaziado, mensagens apagadas...
      // ... exceto esta
      this.success.set({
        key: id === null ? 'FORM.ADDED' : 'FORM.UPDATED',
        params: { name: `${client.firstName} ${client.lastName}`, login: client.login ?? '' },
      });
      await this.reload();
    } catch (e) {
      if (!(e instanceof ApiError)) throw e;
      this.pageError.set(e); // a mensagem geral
      // o erro de cada campo: é entregue ao seu controle, que
      // se torna inválido (ng-invalid); markAsTouched o marca como "tocado"
      // (ng-touched): o Ionic então exibe seu errorText
      for (const [field, key] of Object.entries(e.fields)) {
        const control = this.form.get(field);
        control?.setErrors({ server: key });
        control?.markAsTouched();
      }
    }
  }

  async remove(c: Person): Promise<void> {
    const name = `${c.firstName} ${c.lastName}`;
    if (!(await this.confirm(this.tr.t('FORM.DELETE_CONFIRM', { name })))) return;
    this.clearMessages();
    try {
      await this.api.delete(`/clients/${c.id}`);
      this.success.set({ key: 'FORM.DELETED', params: { name } });
    } catch (e) {
      if (e instanceof ApiError) this.pageError.set(e);
    }
    await this.reload();
  }
}

Naturalmente, nada impede que você também valide os campos no celular (exemplo 08) para responder mais rapidamente ao usuário; no entanto, o servidor deve validar tudo de novo, e seu veredito é final.

Em contrapartida, o [TypeScript] não valida o formato das respostas em tempo de execução, o que a filtragem do [Dart] fazia naturalmente.
