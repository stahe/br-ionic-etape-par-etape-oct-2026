    Este documento é um produto de Claude, a IA da Anthropic. Ele segue o curso “Introdução passo a passo ao framework mobile Flutter”, do qual toma emprestados o roteiro, os exemplos e o estudo de caso, e o curso “Introdução passo a passo ao framework Angular”, do qual toma emprestadas as ferramentas:

    • No curso [Flutter], a aplicação é um aplicativo mobile escrito em [Dart], cujo motor, o [Flutter], renderiza cada pixel por conta própria;
    • No curso de [Angular], a aplicação é uma aplicação web: HTML, CSS e [TypeScript], executados por um navegador;
    • Neste curso, a aplicação é AS DUAS COISAS: uma aplicação web, escrita com [Angular] e com componentes do framework [Ionic], que a ferramenta [Capacitor] empacota em uma aplicação [Android] instalada no celular. O mesmo código, sem nenhuma alteração, também roda em um navegador.

    O servidor, por sua vez, permanece inalterado: é o servidor JSON [RdvMedecins] das lições anteriores, escrito com [NestJS]. E as telas do aplicativo são as que os leitores das outras lições já conhecem (login com CAPTCHA, agenda do médico, janela de consulta, portal do paciente, gerenciamento de médicos e clientes, criação de conta, francês e inglês), adaptadas para a tela de um celular.

    O documento segue a mesma estrutura de seus predecessores: primeiro, numerosos exemplos curtos, cada um centrado em um conceito de [Ionic] ou [Angular], seguidos de um estudo de caso completo, o cliente [Ionic] da aplicação [RdvMedecins], cujos arquivos são todos comentados. Os 25 exemplos têm a mesma numeração e exibem as mesmas telas que os do curso de [Flutter] (e os dos cursos de [React] e [Vue.js] ): o leitor familiarizado com um desses frameworks reconhecerá os mesmos exemplos, escritos no estilo de [Ionic] e [Angular]. Cada exemplo também termina com uma comparação com o [Flutter].

    Pressupõe-se que o leitor conheça os fundamentos da linguagem [TypeScript] e do framework [Angular]: eles são abordados nos cursos “Introdução à linguagem TypeScript por meio de exemplos” e “Introdução passo a passo ao framework Angular”. Mesmo assim, os conceitos de [Angular] utilizados (signals, templates, injeção de dependência, roteador, formulários reativos etc.) são revistos ao longo dos exemplos, conforme se tornam necessários.

    1.1. O papel do Ionic em uma aplicação cliente/servidor

    A aplicação tem duas partes, que se comunicam entre si apenas por meio de requisições HTTP:

    • 1: a aplicação [Ionic], executada no celular, envia uma requisição HTTP ao servidor, por exemplo [GET /api/schedule?doctorId=1&day=2026-10-05];
    • 2: o servidor responde com dados JSON: a agenda desse médico para esse dia. Ele não gera nenhuma página;
    • 3: a partir desses dados, o [Angular] atualiza a tela do celular.

    Esta é exatamente a arquitetura dos clientes [Flutter], [React], [Vue.js] e [Angular]: a única diferença é o que gera a exibição. E, nesse aspecto, o [Ionic] é o oposto do [Flutter]. [Flutter] é um motor de renderização: não depende em nada do navegador e renderiza por conta própria cada pixel da tela. [Ionic], por outro lado, não renderiza nada: é uma biblioteca de web components: novos elementos HTML ([<ion-button>], [<ion-input>], [<ion-list>], [<ion-tabs>]...), criados com a ferramenta [Stencil] da equipe do [Ionic], que qualquer navegador sabe exibir. Esses componentes imitam os componentes nativos do celular em dois “modos”: [md] ([Material Design], a aparência do [Android]) e [ios] (a aparência do [iPhone]). Este curso impõe o modo [md] em todos os lugares, inclusive no navegador. Por serem simples elementos HTML, os componentes do [Ionic] podem ser usados com [Angular], [React] ou [Vue.js]: este curso os utiliza com [Angular] (o pacote [@ionic/angular]).

    A aplicação é, portanto, uma aplicação web comum: uma página HTML, uma folha de estilos e código [JavaScript] compilado a partir de [TypeScript]. É o [Capacitor] (da mesma equipe do [Ionic]) que a transforma em uma aplicação [Android]:

    • [Capacitor] gera um projeto [Android] nativo, cuja única tela é uma WebView: o motor do navegador [Chrome] do celular, em tela cheia, sem barra de endereço. A aplicação web compilada é copiada para esse projeto, e a WebView a carrega na inicialização. Para o usuário, é como qualquer outro aplicativo: um ícone, uma tela de abertura e o botão Voltar do [Android];
    • o código [JavaScript] acessa os recursos do celular (armazenamento, câmera, notificações, geolocalização etc.) por meio de plugins do [Capacitor], que funcionam como uma ponte para o código nativo. Este curso usa dois deles: [@capacitor/preferences] (um pequeno repositório chave-valor no dispositivo, exemplo 20) e [CapacitorHttp] (requisições HTTP feitas pelo código nativo do [Android], exemplos 22 a 25);
    • O mesmo código roda em um navegador, onde os plugins têm uma versão web (o armazenamento do [Capacitor] passa então a usar o [localStorage] do navegador). Assim, desenvolvemos no [Chrome], no tamanho de um celular, usando suas ferramentas de desenvolvimento, e depois passamos para o [Android] para testar.

    As três camadas da aplicação e o que cada uma oferece:

    • [Angular]: o framework da aplicação. Fornece os componentes (uma classe [TypeScript] e um template HTML), os signals (o estado, cujas mudanças atualizam a tela), a injeção de dependência (serviços, estado compartilhado), o roteador (um endereço por tela), os formulários, o cliente HTTP e os “pipes” (formatação). Os leitores do curso de [Flutter] reconhecerão o princípio: a interface é uma função do estado. Nunca modificamos a própria tela: mudamos o estado, e o [Angular] atualiza tudo o que depende dele;
    • [Ionic]: os componentes de interface, que se parecem com os de um aplicativo mobile (barras de ferramentas, listas, campos, botões flutuantes, abas, janelas de alerta, calendário etc.), e a navegação de um aplicativo mobile: uma pilha de páginas, animada como no [Android], da qual o botão Voltar retira a página do topo;
    • [Capacitor]: o aplicativo [Android] e o acesso ao celular.

    Ao contrário do [Flutter], não são necessários pacotes adicionais para a comunicação com um servidor: o [Angular] fornece o cliente HTTP, o roteador, os formulários e a injeção de dependência; o [JavaScript], junto com o objeto [Intl], fornece a formatação de datas e números para cada idioma; a biblioteca [RxJS], incluída com o [Angular], fornece fluxos assíncronos de dados. As traduções (Exemplo 21) ficam a cargo de uma pequena classe escrita especificamente para esse fim, que lê os dicionários JSON.

    1.2. Ferramentas utilizadas

    Os exemplos foram escritos e testados com as seguintes ferramentas (sua instalação é descrita no próximo capítulo e no apêndice):

    • [Node.js] 24 e seu gerenciador de pacotes [npm]: o [Angular CLI] 22 exige o [Node.js] 22.22.3 (ou uma versão 22 mais recente), 24.15 ou superior, ou 26 e posteriores. O [Node.js] também executa o servidor JSON;
    • [Angular CLI] 22.2 (o comando [ng]), o [Angular] 22.2 e o [TypeScript] 6.0;
    • [Ionic] 9.0 (o pacote [@ionic/angular] 9.0.6) e seus ícones, [ionicons] 8.1;
    • [Capacitor] 8.5 (os pacotes [@capacitor/core], [@capacitor/android] e [@capacitor/cli]) e seu plugin [@capacitor/preferences] 8.0;
    • o editor [Visual Studio Code] e suas extensões [Angular Language Service] e [Ionic];
    • [Android Studio], para o SDK [Android], seu JDK e seu gerenciador de emuladores: um emulador [Android] (um celular simulado no computador) ou um celular [Android] real conectado ao computador;
    • o navegador [Chrome], para desenvolver e depurar a aplicação, tanto no computador quanto no celular;
    • o SGBD [MySQL] (ou [MariaDB]), por exemplo, o do [Laragon] no [Windows]: ele é necessário para o servidor JSON, como descrito no capítulo que o apresenta;
    • a ferramenta de linha de comando [curl], que exibe as respostas HTTP brutas.

    Os pacotes utilizados são os dos arquivos [package.json] dos dois projetos [Ionic], que são idênticos: os [@angular/...] 22.2, [@ionic/angular] 9.0, [ionicons] 8.1, [@capacitor/...] 8.5, [@capacitor/app] 8.1, [@capacitor/preferences] 8.0, [rxjs] 7.8 e, somente para desenvolvimento, [typescript] 6.0, [prettier] 3 (formatação do código) e [playwright] 1.56 (capturas de tela).

    1.3. Capturas de tela

    As capturas de tela deste documento foram geradas automaticamente por programas que usam a biblioteca [Playwright] (pastas [captures/] dos dois projetos [Ionic]). O programa [captures/captures.mjs] controla um navegador [Chromium] (a versão livre do [Chrome]) no tamanho de um celular [Android]: 412 x 892 pontos, a 2,625 pixels por ponto, resultando em imagens de 1082 x 2342 pixels. Para cada exemplo, ele executa um “cenário” da pasta [captures/scenarios/]: abre a página do exemplo, interage com ela como um usuário faria (digitando texto, pressionando botões) e, em seguida, salva a tela como um arquivo de imagem.

    São, portanto, capturas reais da aplicação, renderizadas pelo motor do [Chrome], o mesmo usado pela WebView do celular; faltam apenas a barra de status do celular (hora, bateria) e o teclado na tela. O leitor pode recriá-las (a aplicação deve estar em execução; veja abaixo):

    1
2
3
    npx playwright install chromium
npm run captures
node captures/captures.mjs 05 17
    • linha 1: uma única vez: baixa o navegador [Chromium] usado pelo [Playwright];
    • linha 2: recria todas as capturas na pasta [captures/images/];
    • linha 3: recria apenas as dos exemplos 05 e 17.

    As capturas dos exemplos 22 a 25 e do estudo de caso também exigem que o servidor JSON esteja em execução em “modo de teste” para o CAPTCHA (veja o capítulo que descreve o servidor).
