    14. Apêndices

    14.1. Instalação do Node.js

    O [Node.js] é baixado em nodejs.org: selecione a versão LTS (suporte de longo prazo), versão 24 no momento da escrita. O instalador para [Windows] também instala o [npm]. O [Node.js] é necessário tanto para os projetos [Ionic] (o [Angular CLI] 22 exige a versão 22.22 ou superior) quanto para o servidor JSON. Verifique a instalação em um console:

    1
2
    node --version
npm --version

    Se outro projeto exigir uma versão mais antiga do [Node.js], um gerenciador de versões permite instalar várias versões e alternar entre elas: [nvm-windows] no [Windows], [nvm] no [Linux] e no [macOS] ([nvm install 24], depois [nvm use 24]).

    No [Windows], [PowerShell] pode se recusar a executar os comandos [npm] e [npx] ("a execução de scripts está desabilitada neste sistema"): o comando [Set-ExecutionPolicy -Scope CurrentUser RemoteSigned] a habilita para o usuário atual.

    14.2. Instalação do Android Studio e de um emulador

    O [Android Studio] pode ser baixado em developer.android.com/studio. Ele não é usado para escrever código, mas para instalar o SDK e o [Android], fornecer um JDK e criar um emulador (os detalhes estão no capítulo "Configuração do ambiente de desenvolvimento"):

    • na primeira execução, o assistente instala o SDK e o [Android];
    • menu "More Actions" / "SDK Manager", aba "SDK Tools": marque "Android SDK Platform-Tools" ([adb]), "Android Emulator" e "Android SDK Command-line Tools";
    • crie as variáveis de ambiente [ANDROID_HOME] (a pasta do SDK) e [JAVA_HOME] (a subpasta [jbr] do [Android Studio]), de que o [Capacitor] precisa para compilar o aplicativo;
    • menu "More Actions" / "Virtual Device Manager": crie um celular virtual (por exemplo, um "Pixel") usando uma imagem de sistema recente. Clique no botão ▶ para iniciá-lo; [adb devices] o detectará então com o nome [emulator-5554]. Também é possível iniciá-lo sem abrir o [Android Studio]: [npx cap run android] lista os emuladores que você criou — mesmo que estejam parados — e inicia o selecionado; ou, pela linha de comando, o programa [emulator] do SDK: [emulator -list-avds] lista os nomes dos emuladores e [emulator -avd <name>] inicia um deles (no [Windows]: [%ANDROID_HOME%\emulator\emulator.exe]).

    Para um celular real: em Configurações / Sobre o telefone, tocar sete vezes em "Número da versão" exibe as "Opções do desenvolvedor", onde é possível habilitar a "Depuração USB". Ao ser conectado ao computador, o celular pede que você autorize o computador; [adb devices] então o detecta.

    O projeto [Android] criado pelo [Capacitor] (a pasta [android/]) é aberto no [Android Studio] por meio de [npx cap open android]. Entre outras coisas, ele contém a janela [Logcat] (mensagens do aplicativo e do sistema, incluindo as dos plugins do [Capacitor]) e o botão [Run], que faz o mesmo que [npx cap run android].

    14.3. Instalação do Visual Studio Code

    O [Visual Studio Code] é baixado em code.visualstudio.com. O suporte a [TypeScript] e [JavaScript] já vem integrado. No painel de extensões (Ctrl+Shift+X), instale:

    • a extensão [Angular Language Service] (da equipe [Angular]): autocompletar e validação em templates ([HTML] — propriedades e métodos da classe, inputs de componentes e atributos de componentes do [Ionic]), navegação de um template até o código de sua classe (F12) e exibição dos erros de compilação do template enquanto você digita;
    • a extensão [Ionic] (da equipe [Ionic]): um painel que inicia o aplicativo no navegador ou em um dispositivo [Android], gerencia os plugins do [Capacitor] e avisa os usuários sobre atualizações dos pacotes [Ionic] e [Capacitor] ;
    • opcionalmente, a extensão [Prettier], que formata o código ao salvar, segundo as regras especificadas no arquivo [.prettierrc] dos projetos.

    Abra um projeto pelo menu File / Open Folder (a pasta [examples_ionic], por exemplo) e abra um console pelo menu Terminal / New Terminal; é ali que você digita [npm install], [npm start], [npx ng build], [npx cap run android]... O arquivo [.vscode/launch.json] dos projetos também permite iniciar o aplicativo com F5: o [VS Code] então executa [npm start], abre o [Chrome] no aplicativo, e você pode definir breakpoints diretamente no código [TypeScript] dentro do editor.

    14.4. Ferramentas de desenvolvimento do Chrome

    As ferramentas de desenvolvedor do [Chrome] estão para uma aplicação [Ionic] assim como o [Flutter DevTools] está para uma aplicação [Flutter]. Você pode abri-las com F12 (ou Ctrl+Shift+I). Suas abas mais úteis são:

    • a barra de emulação de dispositivos (Ctrl-Shift-M): a aplicação redimensionada para o tamanho de um celular (um modelo da lista ou dimensões especificadas), com eventos de toque. É assim que você desenvolve a aplicação antes de passar para o [Android];
    • "Elements": a árvore de elementos da página e, para cada elemento, seus estilos (que podem ser editados em tempo real). O ícone de seta no canto superior esquerdo permite clicar em um elemento da página para localizá-lo na árvore. Ali você vê as tags [<ion-...>] e, dentro de cada uma, seu "shadow DOM": os elementos HTML que a compõem. Essa ferramenta responde à pergunta "Por que este elemento não está no lugar certo?";
    • "Console": as mensagens da aplicação ([console.log()]) e os erros, junto com o arquivo e a linha ([TypeScript]) de onde se originaram;
    • "Sources": o código da aplicação ([TypeScript]) (por meio dos "source maps" da configuração [development]), onde os breakpoints são definidos;
    • "Network": as requisições (HTTP) da aplicação, com seus cabeçalhos e corpos: aqui você vê o cookie de token sendo enviado e recebido (no navegador);
    • "Application": o armazenamento da página ([localStorage], onde a extensão [@capacitor/preferences] guarda seus valores em um navegador) e seus cookies.

    A extensão [Angular DevTools] (a ser instalada pela [Chrome Web Store]) adiciona uma aba "Angular": a árvore de componentes [Angular] da tela e, para cada componente, seus inputs, signals e propriedades, que podem ser modificados em tempo real; sua aba "Profiler" mostra o que o [Angular] atualizou — e quanto tempo levou — após cada evento.

    As mesmas ferramentas podem depurar a aplicação instalada no emulador ou no celular. No [Chrome] do computador, abra o endereço [chrome://inspect]: a página lista os dispositivos conectados via [adb] e, para cada um, a WebView das aplicações em execução que podem ser depuradas (isso vale para aplicações [Capacitor] compiladas em modo "debug", como as iniciadas por [npx cap run android]). O link "Inspect" abre uma janela de ferramentas de desenvolvimento, ligada à WebView da aplicação, com a tela do celular exibida à esquerda: ali você encontra as abas "Elements", "Console", "Sources", "Network" e outras... Como as requisições feitas pelo [CapacitorHttp] passam pelo código nativo do [Android], nem todas aparecem na aba "Network": a janela [Logcat] do [Android Studio] as exibe.

    14.5. Instalação do MySQL com o Laragon

    O servidor JSON requer o [MySQL] (ou o [MariaDB]). O [Laragon] (laragon.org) instala um deles no [Windows], pronto para uso, com a ferramenta de administração [HeidiSQL]. Após a instalação:

    • o botão "Start All" inicia o servidor [MySQL] na porta 3306;
    • o usuário [root] não tem senha: esses são os valores padrão do arquivo [.env.example] do servidor;
    • No [HeidiSQL] (botão "Database"), o item de menu File / Run SQL executa o script [database/dbrdvmedecins2.sql].

    No [Linux] ou no [macOS], instale o [MySQL] ou o [MariaDB] usando o gerenciador de pacotes do sistema e execute o script com o cliente de linha de comando: [mysql -u root -p < database/dbrdvmedecins2.sql].

    14.6. Instalação do curl

    O [curl] vem incluído nas versões 10 e 11 do [Windows] , [macOS], e na maioria das distribuições do [Linux]. Verifique sua versão:

    1
    curl --version

    A opção [--json], usada neste documento, está disponível desde a versão 7.82 (2022). Se você usa uma versão mais antiga, substitua [--json @file] por [-H "Content-Type: application/json" -d @file] ou instale uma versão recente a partir de curl.se.

    No [PowerShell], é preciso digitar [curl.exe], não [curl]: no [PowerShell], [curl] é um alias de outro comando ([Invoke-WebRequest]), que não inclui as opções do [curl]. O prompt de comando ([cmd]) não tem esse problema.
