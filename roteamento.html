    5. Roteamento

    Uma aplicação tem várias telas. Na web, cada tela tem um endereço (/ex17/doctors/2): ela pode ser referenciada, aberta por um link, recarregada ou protegida por guards. O [Angular] gerencia esses endereços por meio de seu roteador (o pacote [@angular/router]), que usamos desde o primeiro exemplo: a página inicial da aplicação de exemplo associa o endereço /ex01 à página do Exemplo 01, /ex02 à página do Exemplo 02, e assim por diante. O [Ionic] não substitui esse roteador: ele se apoia nele e acrescenta as funcionalidades esperadas de um aplicativo móvel. Seu componente [<ion-router-outlet>]organiza as páginas em uma pilha: uma nova página é empilhada sobre a anterior (com a animação do Android), o botão Voltar do celular a remove da pilha, e a página anterior — que permanece na memória — reaparece exatamente como foi deixada. Ele combina o [Navigator] do [Flutter] e o pacote [go_router].

    5.1. Exemplo 17: o roteador

    O Exemplo 17 tem seis páginas: uma página inicial, uma lista de médicos, o perfil de um médico, uma página de busca, uma página “About” carregada sob demanda e uma página para endereços desconhecidos. As cinco primeiras são agrupadas em um “shell”, com uma barra de abas na parte inferior da tela (quatro abas: a página de detalhes de um médico pertence à aba Doctors).

    // =========================================================================
// src/app/ex17-router/routes.ts - as ROTAS do exemplo 17
// -------------------------------------------------------------------------
// Uma aplicação tem várias telas ("páginas"). O ROTEADOR do Angular
// associa um ENDEREÇO (um path, como na web: /ex17/doctors/2) a
// uma página. O Ionic se apoia nele: seu <ion-router-outlet> o transforma em uma
// PILHA de páginas (empilhamos, desempilhamos, o botão Voltar do Android desempilha).
// Estas rotas são as FILHAS da rota /ex17 de app.routes.ts
// (loadChildren): seus paths são relativos a /ex17.
//   'doctors/:id'    :id é um parâmetro (/ex17/doctors/2 -> id = "2");
//   children         rotas exibidas DENTRO do "shell" (a barra
//                    superior, a barra de abas na parte inferior);
//   redirectTo       um redirecionamento: o endereço antigo leva ao novo;
//   '**'             o "curinga": qualquer endereço que nenhuma rota reconhece;
//   title            o título do documento (aba do navegador);
//   loadComponent    carregamento ADIADO: o código da página só é
//                    baixado na primeira visita.
// =========================================================================

import { ResolveFn, Routes } from '@angular/router';
import { Shell } from './shell';
import { doctors } from './data';
import { Home } from './pages/home.page';
import { DoctorDetail } from './pages/doctor-detail.page';
import { DoctorList } from './pages/doctor-list.page';
import { NotFoundPage } from './pages/not-found.page';
import { Search } from './pages/search.page';

// o título da página de um médico, calculado a partir do parâmetro :id do endereço
const doctorTitle: ResolveFn<string> = (route) => {
  const doctor = doctors.find((m) => m.id === Number(route.paramMap.get('id')));
  return doctor ? `${doctor.firstName} ${doctor.lastName}` : 'Unknown doctor';
};

export const routes: Routes = [
  {
    // o shell (Shell) contém a barra de abas; suas rotas
    // filhas são exibidas DENTRO do shell, acima da barra
    path: '',
    component: Shell,
    children: [
      // /ex17 sozinho: vamos para a aba inicial
      { path: '', redirectTo: 'home', pathMatch: 'full' },
      { path: 'home', title: 'Home', component: Home },
      { path: 'doctors', title: 'Doctors', component: DoctorList },
      // uma página com um PARÂMETRO: /ex17/doctors/2; ela começa com
      // 'doctors': pertence à aba Doctors, na qual ela
      // empilha uma página acima da lista
      { path: 'doctors/:id', title: doctorTitle, component: DoctorDetail },
      // /ex17/search?q=pediatrician: o parâmetro q é um parâmetro de QUERY
      { path: 'search', title: 'Search', component: Search },
      // carregamento adiado: import() é um import DINÂMICO
      // (uma Promise); o código da página é colocado em um arquivo separado
      {
        path: 'about',
        title: 'About',
        loadComponent: () => import('./pages/about.page').then((m) => m.About),
      },
      // um redirecionamento: a rota não tem página, ela envia para outro endereço
      { path: 'physicians', redirectTo: 'doctors' },
    ],
  },
  // qualquer outro endereço sob /ex17: a página de não encontrado, FORA do shell
  { path: '**', title: 'Page not found', component: NotFoundPage },
];

    Uma rota associa um caminho a uma página. As rotas do Exemplo 17 ficam em sua pasta, e a rota /ex17 da aplicação as carrega por meio de [loadChildren] (abordado adiante): são rotas filhas de /ex17, e seus caminhos são relativos a /ex17 ([home] refere-se ao endereço /ex17/home).

    • Linhas 30–33: uma função do tipo [ResolveFn<string>], que calcula o título da página de um médico com base no parâmetro [:id] da URL ([route.paramMap.get('id')]). A propriedade [title] de uma rota é o título do documento (a aba do navegador, na web): uma string ou uma função como essa. É o equivalente do widget [Title] do [Flutter];
    • Linhas 36–41: o shell do exemplo. A rota não tem caminho próprio ([path: '']); ela exibe o componente [Shell] (a barra superior e a barra de abas), e suas rotas filhas ([children]) são exibidas DENTRO do shell. É o equivalente de [ShellRoute] do [go_router];
    • linha 43: o endereço /ex17 sozinho é redirecionado para /ex17/home. [pathMatch: 'full']: a rota só se aplica se o restante do endereço estiver vazio (caso contrário, o caminho vazio — que é o início de todo endereço — sempre se aplicaria);
    • linhas 44–45: uma rota padrão: seu caminho, seu título e seu componente de página;
    • linha 49: uma rota com um parâmetro: [doctors/:id], em que [:id] é um parâmetro ([/ex17/doctors/2]: [id] equivale a ["2"], que é sempre uma string). Com o [go_router], essa rota era aninhada na da lista; aqui, ela fica ao lado. Seu caminho começa com [doctors]: para o [Ionic], ela pertence à aba Doctors, e sua página é empilhada acima da lista, na pilha dessa aba;
    • linha 51: a busca. Seus parâmetros de consulta (depois de [?]: [/ex17/search?q=pediatrician]) não aparecem no caminho da rota: qualquer rota pode aceitá-los;
    • Linhas 54–58: carregamento tardio. [loadComponent] é uma função que retorna uma [Promise]: [import('./pages/about.page')] é uma importação dinâmica do [JavaScript], que carrega o arquivo quando é executada, e [then] extrai dele o componente. A compilação ([ng build]) coloca então o código da página em um arquivo [JavaScript] separado, que é baixado na primeira visita à página. É o equivalente da importação do [Dart] com [deferred as];
    • linha 60: um redirecionamento: a rota não tem página; ela redireciona para outro endereço. [redirectTo] também pode ser uma função que calcula o endereço;
    • linha 64: a rota curinga [**] corresponde a qualquer endereço que nenhuma rota anterior tenha correspondido (o roteador tenta as rotas em ordem). Ela é colocada fora do shell: a página “page not found” tem sua própria barra de cabeçalho. É o equivalente de [errorBuilder] do [go_router].

    // =========================================================================
// src/app/ex17-router/shell.ts - o "shell" do exemplo 17
// -------------------------------------------------------------------------
// A barra superior, a barra de abas na parte inferior e, entre as duas, a página
// da rota atual. É o componente <ion-tabs> do Ionic:
//   - <ion-tab-bar slot="bottom">: a barra de abas, na parte inferior;
//   - <ion-tab-button tab="doctors">: uma aba; tocá-la leva ao
//     endereço /ex17/doctors. A aba ativa é aquela cujo nome é o
//     primeiro segmento do endereço (depois de /ex17): /ex17/doctors/2 -> Doctors;
//   - cada aba tem sua PRÓPRIA pilha de páginas: podemos entrar no
//     detalhe de um médico, mudar para a aba Search, voltar à
//     aba Doctors... e encontrar o detalhe novamente.
// =========================================================================

import { Component, computed, inject } from '@angular/core';
import { Router } from '@angular/router';
import {
  IonBackButton, IonButtons, IonHeader, IonIcon, IonLabel, IonTabBar, IonTabButton, IonTabs, IonTitle, IonToolbar,
} from '@ionic/angular';
import { addIcons } from 'ionicons';
import { home, informationCircle, people, search } from 'ionicons/icons';
import { DeferredLoading } from './pages/deferred-loading';

// as abas: o nome da aba (= o path, depois de /ex17), o rótulo, o ícone
const tabs = [
  { tab: 'home', label: 'Home', icon: 'home' },
  { tab: 'doctors', label: 'Doctors', icon: 'people' },
  { tab: 'search', label: 'Search', icon: 'search' },
  { tab: 'about', label: 'About', icon: 'information-circle' },
];

@Component({
  selector: 'app-ex17-shell',
  imports: [
    IonTabs, IonTabBar, IonTabButton, IonIcon, IonLabel, IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle,
    DeferredLoading,
  ],
  templateUrl: './shell.html',
  styles: `
    .address {
      background: var(--ion-color-light);
      color: var(--ion-color-light-contrast);
      padding: 8px;
      font-family: monospace;
      font-size: 12px;
    }
  `,
})
export class Shell {
  readonly tabs = tabs;
  private readonly router = inject(Router);

  // o endereço atual. lastSuccessfulNavigation é um SIGNAL do roteador:
  // a última navegação bem-sucedida; finalUrl: seu endereço, depois dos
  // redirecionamentos. decodeURIComponent: %20 volta a ser um espaço
  readonly address = computed(() => {
    const navigation = this.router.lastSuccessfulNavigation();
    return navigation?.finalUrl ? decodeURIComponent(this.router.serializeUrl(navigation.finalUrl)) : '';
  });

  constructor() {
    // os ícones usados pelo template
    addIcons({ home, people, search, informationCircle });
  }
}

    O shell é o componente [<ion-tabs>] do [Ionic]: uma barra de abas e, acima dela, a página da aba selecionada.

    • linhas 25–30 (shell.ts): as abas: um nome (que também é o caminho depois de /ex17), um rótulo e um ícone;
    • linhas 56–59 (shell.ts): o endereço atual, um signal calculado ([computed]). O roteador expõe signals: [lastSuccessfulNavigation()], a última navegação bem-sucedida, e [currentNavigation()], a navegação em andamento (abordada adiante). [finalUrl] é o endereço de destino, após os redirecionamentos; [serializeUrl] o converte em uma string; [decodeURIComponent] decodifica os caracteres codificados ([%20] volta a ser um espaço). Como o signal é relido a cada navegação, o endereço exibido acompanha;
    • linha 63 (shell.ts): os ícones usados pelo template;
    • linhas 7–18 (shell.html): a barra superior. [<ion-tabs>] coloca os elementos marcados com [slot="top"] acima das páginas das abas, e os demais abaixo. O botão Voltar dessa barra fecha todo o shell: ele leva você de volta ao menu de exemplos;
    • linha 15 (shell.html): o endereço atual;
    • linha 17 (shell.html): uma barra de progresso, exibida durante a navegação (veja adiante);
    • linhas 20–21 (shell.html): o próprio [<ion-tabs>] coloca, entre as duas barras, um [<ion-router-outlet>]: a página da rota filha atual. Nós não o escrevemos;
    • linhas 24–31 (shell.html): a barra de abas inferior ([<ion-tab-bar slot="bottom">]), típica de um aplicativo móvel, é o equivalente de [NavigationBar] do [Flutter]. Cada [<ion-tab-button [tab]="...">] é uma aba; tocar nela leva ao endereço /ex17/<tab name>.

    Duas diferenças em relação ao [go_router]:

    • a aba ativa não é calculada pelo código: o [<ion-tabs>] a deduz da URL (a aba cujo nome é o primeiro segmento da URL, depois de /ex17: [/ex17/doctors/2] refere-se à aba [doctors]);
    • Cada aba tem sua própria pilha de páginas. Se você vir os detalhes de um médico, mudar para a aba Search e depois voltar à aba Doctors, verá novamente os detalhes do médico, e o botão Voltar o leva de volta à lista. Esse é o comportamento padrão dos aplicativos móveis (como os de [Android] e [iOS]).

// O roteador entrega o parâmetro :id do endereço ao INPUT id da página
// (input), uma STRING ("2"): é o withComponentInputBinding() (main.ts).

// mesma página e apenas muda o valor do input: o médico
// exibido, calculado (computed) a partir dele, acompanha.
// Navegação pelo CÓDIGO: NavController, o serviço de navegação do Ionic.
// =========================================================================

import { Component, computed, inject, input } from '@angular/core';
import { IonButton, IonContent, IonRouterOutlet, IonText, NavController } from '@ionic/angular';
import { doctors } from '../data';

@Component({
  selector: 'app-ex17-doctor-detail',
  imports: [IonContent, IonButton, IonText],
  templateUrl: './doctor-detail.page.html',
})
export class DoctorDetail {
  // o parâmetro :id do endereço
  readonly id = input.required<string>();

  readonly doctor = computed(() => doctors.find((m) => m.id === Number(this.id())));
  // o número do próximo médico: 1 -> 2 -> 3 -> 1
  readonly next = computed(() => ((this.doctor()?.id ?? 0) % doctors.length) + 1);

  private readonly outlet = inject(IonRouterOutlet);

  back(): void {
    // canGoBack: há uma página por baixo? (não, se chegamos
    // diretamente a este endereço, na web)
    if (this.outlet.canGoBack()) {
      this.outlet.pop();
    } else {
      this.navCtrl.navigateBack('/ex17/doctors');
    }
  }

    // replaceUrl: o endereço SUBSTITUI o endereço atual no histórico
    // (sem push: o botão Voltar leva de volta à lista)
    this.navCtrl.navigateForward(['/ex17/doctors', this.next()], { replaceUrl: true });
  }
}

// src/app/ex18-guards/session.ts - uma sessão SIMULADA (sem servidor)
// -------------------------------------------------------------------------
// O usuário conectado deve ser conhecido pelas PÁGINAS (a barra superior,
// a agenda) e pelos GUARDS do roteador (funções, que não são
// componentes). Nós o guardamos em um SERVIÇO, um único objeto que todos
// obtêm com inject(Session) (veja o exemplo 14):
//   - um signal privado, o estado;
//   - uma visão somente leitura desse signal;
//   - métodos para modificá-lo.
// Quem lê o signal (os templates) é notificado quando ele muda.
// (O exemplo 23 fará a mesma coisa com um servidor real.)
// =========================================================================

import { Injectable, signal } from '@angular/core';

export type Role = 'ADMIN' | 'DOCTOR' | 'USER';

export interface User {
  login: string;
  role: Role;
}

// três contas "fixas no código" (senha = login)
const accounts: Record<string, Role> = { admin: 'ADMIN', pelissier: 'DOCTOR', martin: 'USER' };

// providedIn: 'root': UMA única instância, para toda a aplicação
@Injectable({ providedIn: 'root' })
export class Session {
  // o estado: null, ninguém está conectado
  private readonly _user = signal<User | null>(null);
  // asReadonly: podemos ler o signal, não modificá-lo
  readonly user = this._user.asReadonly();

  logIn(login: string, password: string): boolean {
    const role = accounts[login];
    if (role === undefined || password !== login) {
      return false;
    }
    this._user.set({ login, role });
    return true;
  }

  logOut(): void {
    this._user.set(null);
  }
}

    O usuário logado precisa ser reconhecido pelas páginas (a barra superior, a agenda) e pelos guards do roteador — elementos que não são componentes. Ele é armazenado em um serviço (veja o Exemplo 14), um objeto único que todos obtêm por meio de [inject(Session)]:

    • linhas 17–22: os papéis (um tipo “union” formado por três strings) e o usuário;
    • linha 25: três contas “fixas no código” (senha = login): um objeto que associa um login a um papel ([Record<string, Role>]);
    • linha 28: [providedIn: 'root']: uma única instância do serviço para toda a aplicação;
    • linhas 31–33: o estado, um signal privado ([null]: ninguém está logado), e sua visão somente leitura ([asReadonly()]): os demais podem lê-lo, mas somente os métodos do serviço podem modificá-lo;
    • linhas 35–42: a conexão, simulada. Ela modifica o signal: tudo o que o lê (templates, signals calculados) acompanha. É o [notifyListeners()] do [ChangeNotifier] do [Flutter], sem precisar escrevê-lo. (O Exemplo 23 fará o mesmo com um servidor de verdade.)

// src/app/ex18-guards/routes.ts - rotas PROTEGIDAS por guards
// -------------------------------------------------------------------------
// canActivate: a lista dos GUARDS de uma rota, funções (do tipo
// CanActivateFn) que o roteador chama ANTES de ir até ela. Um guard recebe
// a rota solicitada e o estado da navegação (state.url: o endereço
// solicitado), e retorna:
//   - true: a navegação continua;
//   - false: ela é cancelada;
//   - uma UrlTree (um endereço construído pelo roteador): a navegação
//     é substituída por uma navegação para esse endereço.
// Um guard pode usar inject(): ele é chamado em um "contexto
// de injeção".
//
// É o equivalente, no lado do cliente, dos guards do NestJS (JwtAuthGuard,
// RolesGuard) - com uma diferença FUNDAMENTAL: um guard de cliente é
// apenas uma conveniência. A aplicação está nas mãos do usuário, que
// pode modificá-la à vontade. A proteção real dos dados continua sendo
// a do SERVIDOR (veja o capítulo sobre a caixa-preta).
// =========================================================================

import { inject } from '@angular/core';
import { CanActivateFn, Router, Routes } from '@angular/router';
import { Shell } from './shell';
import { Home } from './pages/home.page';
import { Schedule } from './pages/schedule.page';
import { Login } from './pages/login.page';
import { Role, Session } from './session';

// o guard "login obrigatório": sem login -> para a página de login,
// lembrando para onde queríamos ir (parâmetro returnUrl)
export const loginRequired: CanActivateFn = (route, state) => {
  if (inject(Session).user() === null) {
    return inject(Router).createUrlTree(['/ex18/login'], { queryParams: { returnUrl: state.url } });
  }
  return true;
};

// o guard "papel obrigatório": uma função que CONSTRÓI um guard
export function roleRequired(...roles: Role[]): CanActivateFn {
  return (route, state) => {
    const u = inject(Session).user();
    if (u === null || !roles.includes(u.role)) {
      // logado, mas sem o papel adequado: volta para a página inicial, com um motivo
      return inject(Router).createUrlTree(['/ex18'], { queryParams: { denied: state.url } });
    }
    return true;
  };
}

export const routes: Routes = [
  {
    path: '',
    component: Shell,
    children: [
      { path: '', pathMatch: 'full', component: Home },
      { path: 'login', component: Login },
      { path: 'schedule', canActivate: [loginRequired], component: Schedule },
      {
        path: 'administration',
        // os guards, em ordem: vence o primeiro que não retornar true
        canActivate: [loginRequired, roleRequired('ADMIN')],
        // o código da página só é carregado depois que os guards são superados
        loadComponent: () => import('./pages/administration.page').then((m) => m.Administration),
      },
      // qualquer outro endereço (nenhuma rota corresponde): volta para a página inicial
      { path: '**', redirectTo: '' },
    ],
  },
];

    Um guard de ativação é uma função do tipo [CanActivateFn], colocada na lista [canActivate] de uma rota. O roteador a chama antes de prosseguir para essa rota; ela recebe a rota solicitada e o estado da navegação ([state.url]: o endereço solicitado) e retorna:

    • [true]: a navegação continua;
    • [false]: a navegação é cancelada;
    • uma [UrlTree], um endereço gerado pelo roteador ([router.createUrlTree]): a navegação é substituída pela navegação para esse endereço.

    Um guard também pode retornar uma [Promise] ou um [Observable] com um desses valores (para consultar um servidor, por exemplo). O código:

    • linhas 32–37: o guard “login obrigatório”: não está logado? Redireciona para a página de login, mantendo o destino pretendido (parâmetro de requisição [returnUrl]). O guard usa [inject()]: o roteador o chama em um “contexto de injeção”;
    • linhas 40–49: o guard “papel obrigatório” é CONSTRUÍDO por uma função, que recebe os papéis permitidos ([...roles]: quantos parâmetros se quiser, agrupados em um array) e retorna o guard. Logado, mas sem o papel correto: redirecionado para a página inicial, com um motivo (parâmetro [denied]);
    • linhas 52–55: o shell e suas rotas filhas, como no Exemplo 17;
    • linha 58: a página da agenda exige que o usuário esteja logado;
    • linhas 59–65: a administração exige que o usuário esteja logado E tenha o papel ADMIN. Os guards da lista são chamados em ordem; o primeiro que não retorna [true] vence (neste caso, era a cadeia de [??] para [go_router]). O código da página é carregado ([loadComponent]) somente depois que os guards são superados;
    • linha 67: qualquer outro endereço sob /ex18 redireciona para a página inicial.

    Este é o equivalente, no cliente, das proteções do servidor [NestJS] ([JwtAuthGuard], [RolesGuard]), com uma fundamental diferença: um guard no cliente é apenas uma conveniência (para evitar exibir uma tela desnecessária). A aplicação está nas mãos do usuário, que pode modificá-la à vontade; a verdadeira proteção dos dados continua no servidor, que reverifica tudo a cada requisição (veja o capítulo sobre a caixa-preta).

    Uma diferença em relação ao [go_router]: sua opção [refreshListenable] reavaliava os guards da página atual a cada mudança de sessão (você era redirecionado para a página de login se saísse da agenda). O roteador do [Angular] só chama os guards durante a navegação. É por isso que o logout (descrito mais adiante) é seguido de uma navegação para a página inicial.

    // =========================================================================
// src/app/ex18-guards/pages/login.page.ts - a página de login
// -------------------------------------------------------------------------
// Depois do login, enviamos o usuário de volta à página que ele queria
// abrir (parâmetro ?returnUrl=... colocado pelo guard), ou à página inicial.
// =========================================================================

import { Component, inject, input, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { Router } from '@angular/router';
import { IonButton, IonCard, IonCardContent, IonInput, IonText } from '@ionic/angular';
import { Session } from '../session';

@Component({
  selector: 'app-ex18-login',
  imports: [FormsModule, IonCard, IonCardContent, IonInput, IonButton, IonText],
  templateUrl: './login.page.html',
})
export class Login {
  // o endereço solicitado, colocado pelo guard loginRequired
  readonly returnUrl = input<string>();

  // os campos do formulário e o erro: signals
  readonly login = signal('');
  readonly password = signal('');
  readonly error = signal(false);

  private readonly session = inject(Session);
  private readonly router = inject(Router);

  submit(): void {
    if (!this.session.logIn(this.login().trim(), this.password())) {
      this.error.set(true);
      return;
    }
    // só aceitamos um caminho INTERNO: começa com /, mas não com //
    // (//site.com/... designa OUTRO site) - nenhum redirecionamento para outro site
    const r = this.returnUrl();
    const internal = r !== undefined && r.startsWith('/') && !r.startsWith('//');
    this.router.navigateByUrl(internal ? r : '/ex18');
  }
}

    Os guards do [Angular] também existem em outras formas: [canMatch] (a rota nem sequer é reconhecida se o guard recusar: seu código não é baixado), [canDeactivate] (sair da página: “Descartar as alterações?”), [canActivateChild] (para todas as rotas filhas de uma rota).
